## Бэклог

- **BL-1** — Offline sync: очередь изменений при отсутствии сети + разрешение конфликтов (last-write-wins по `updatedAt`).
- **BL-2** — Менеджер тегов: переименование/слияние тегов по всем модулям.
- **BL-3** — 📤 Экспорт всего в JSON (кнопка «скачать всё») — доп. бэкап и anti-lock-in.
- **BL-4** — Шаринг вишлиста по read-only ссылке.
- **BL-5** — Шаблоны записей (частые заготовки для дневника/идей).
- **BL-6** — Mood-трекер в дневнике + простая статистика по настроению.
- **BL-7** — Drag-reorder в списках задач/вишлистов.
- **BL-8** — Dark mode (инверсия токенов).
- **BL-9** — Разбор инбокса «в один тап» → конверт записи в нужный модуль.
- **BL-10** — Повторяющиеся задачи/напоминания (RRULE).
- **BL-11** — Bot API `sendMessage` требует `chat_id` получателя — добавлен env `NOTIFY_CHAT_ID`
  сверх исходного списка в CLAUDE.md (без него `/api/cron/reminders` не может слать пуши).
  На будущее: бот сам ловит `/start`, сохраняет свой `chat_id` как служебную запись в канале-БД —
  тогда доп. env не нужен.
- **BL-12** — `next-pwa` не обновлялся с 2022 и не совместим с Turbopack (дефолт в Next.js 16,
  используемом в этом проекте) — заменён на нативный `app/manifest.ts` (файловая конвенция Next)
  + рукописный `public/sw.js`, который кэширует только offline-фолбэк для навигации (не данные —
  они должны быть свежими из Telegram). Если понадобится полноценный precaching — смотреть
  `@serwist/next` (актуальный форк next-pwa под App Router/Turbopack).
- **BL-13** — Резолвинг entity канала-БД (`lib/tg/repo.ts: resolveChannel`) на холодном старте
  падает обратно на полный обход `iterDialogs()`, если GramJS ещё не закэшировал access_hash
  канала. Первый запрос после деплоя/рестарта serverless-функции может быть медленным. Смягчить:
  убедиться, что аккаунт под `TELEGRAM_SESSION` уже открывал список диалогов с этим каналом.
- **BL-14** — Лимит сообщения Telegram (~4096 символов) ограничивает размер одной записи
  (сейчас `lib/tg/repo.ts` бросает ошибку при JSON >4000 байт). Не проблема для inbox/task/
  reminder, но для дневника/документов в v2–v3 потребуется стратегия (разбивка на несколько
  сообщений или media+caption вместо чистого текста).
- **BL-15** — Поиск (`/api/search`) — это MTProto `messages.search` по сырому JSON-тексту
  сообщения: точные подстроки работают, но это не fuzzy и не учитывает морфологию. Ок для v1,
  пересмотреть, если станет неудобно с ростом числа записей.
- **BL-16** — Anton и Archivo Black (шрифты для заголовков из CLAUDE.md) не поддерживают
  кириллицу — русские заголовки молча падали на тонкий системный шрифт (видно на скриншоте
  при живом тестировании). Заменил display-шрифт на Montserrat 800/900 (латиница + кириллица,
  тот же дух «жирный чёрный»). Стоит показать Марте вживую и подтвердить, устраивает ли замена,
  или подобрать другой bold-шрифт с кириллицей.

_Правило: любая новая находка/edge-case/техдолг → сюда пунктом BL-…, ready to paste._
